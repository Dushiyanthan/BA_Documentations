# Smart Learning Management System (LMS) — Business Analysis & QA Portfolio

## 1. Project Overview

This repository contains Business Analysis (BA) and Quality Assurance (QA) documentation developed for a Smart Learning Management System (LMS) academic project.

The purpose of this portfolio is to demonstrate requirements analysis, functional documentation, Agile backlog management, process modelling, test design, and requirements traceability.

The proposed Smart LMS uses student data, academic performance information, data analytics, and machine learning to support student performance monitoring and identify students who may be at risk academically.

## 2. Project Objectives

- Define the business objectives, scope, and requirements of the Smart LMS.
- Document functional requirements and expected system behaviour.
- Organise system functionality into epics, user stories, and acceptance criteria.
- Represent key workflows using process flow diagrams.
- Design test cases to validate functional behaviour and data accuracy.
- Establish traceability between requirements, user stories, workflows, and test cases.

## 3. Documentation Included

**Business Requirements Document (BRD)**
Defines the business context, objectives, scope, stakeholders, and high-level business requirements.
**Functional Requirements Document (FRD)**
Describes the expected system functionality, business rules, and system behaviour.
**Product Backlog**
Organises system requirements into prioritised backlog items.
**Epics, User Stories, and Acceptance Criteria**
Describes system features from the users' perspectives and defines the conditions that must be satisfied for each story to be accepted.
**Process Flow Diagrams**
Illustrates key workflows, activities, and decision points within the system.
**Test Cases**
Defines test scenarios, preconditions, test steps, test data, and expected results for validating system functionality.


## 4. Key Functional Areas

The documentation covers the following areas, subject to the defined project scope:

- Student data management and validation
- Academic performance analytics
- Student performance dashboards
- Machine learning-based student risk prediction
- Notifications for students identified as at risk
- Learning management workflows, where included in scope

## 6. Requirements Traceability

Traceability is used to connect business requirements to functional requirements, user stories, process flows, and test cases.

This helps identify missing test coverage, maintain consistency between documents, and verify that test scenarios address defined requirements.

## 7. Project Context

The Smart LMS originated as an academic project. The business analysis and QA artefacts in this repository have been prepared and refined as portfolio documentation to demonstrate requirements analysis and software testing practices.

The documents should be interpreted according to their stated scope. Proposed requirements or assumptions are not necessarily implemented features of the original academic system.

## 8. Scope and Limitations

This repository focuses on requirements documentation and QA artefacts. The presence of a requirement or test case does not, by itself, indicate that the corresponding feature has been implemented or that the test has been executed.

Test execution results should only be reported where actual testing evidence is available.

## 9. Intended Audience

This portfolio is intended for recruiters, hiring managers, Business Analysts, and QA professionals who wish to review examples of requirements documentation, Agile artefacts, process modelling, and test design.
